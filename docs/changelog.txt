0.166

0.165

- Fixed scroll materials with scroll rates above 127 rendering incorrectly in WorldEdit.

0.162

- Added Grass Patch support to the editor. ODFs with the `grasspatch` class label will now be shown as they would appear ingame, almost. Unlike leaf patches grass patches do not include a seed in their ODF so their exact particle layout depends on the game's random state when it first creates one of the grass patches. Which effectively makes it impossible to do a truly accurate preview for them in the editor. However I believe that there is still value in previewing them (even if it is slightly inaccurate).Selection for these objects is based on the bounds defined in the ODF.
- Added missing Name property to path propert selector.

- Fixed placement mode not being reset when using Object Class Browser to create an object when another creation tool was active.
- Fixed Damage Regions incorrectly using 1.0 as the default for unset scales instead of 0.0.

0.160

- Added "Repair World Requirements" tool to World Requirements (.req) Editor. It will recreate (and thus repair) the world's .req. The repaired .req will not include any custom .req entries you have added but it will include correct references for all the world's dependencies, including things like water normal maps and shadow region env maps.
- Added "No Assets from Other Worlds" setting to turn off using assets from world folders other than the common one and currently loaded one. Off by default for now to avoid excessively garbage collecting thumbnails. Don't be worried about turning it on though if it's useful to you.

- Fixed priority ordering issue with project level assets.

Side Note: You do not need to copy from or into the widgets, they place the values into the clipboard (as `-35.44 -62.06 -137.599` for instance) and take values from the clipboard. 0.143

- Added builtin Model Munge. It is faster, has better errors/warnings, outputs (in theory) more optimized models and even has (optional) support for large texture coordinates. See the full docs here: https://github.com/PrismaticFlower/WorldEdit/blob/master/docs/user/Builtin%20Mungers/Model%20Munge.md
- Added support for platform specific ODF properties. (i.e. "PS2:MaxHealth = 200.0")
- Added "Use Builtin ModelMunge", "Use Builtin OdfMunge" and "Use Builtin TextureMunge" munge config options. Replaces "Use Builtin Munge Tools".
- Added "Texture Quality" munge config option. Controls the quality of compressed textures when using WorldEdit's builtin texture munge. You can use it to trade off quality for munge speed or vice versa.
- Added "Deploy Checkdate" munge config option. On by default. This speeds up deploying an addon when only some .lvl files have changed by comparing the last write date.
- Added "Deploy Allow Hard Links" munge config option. Off by default. This can drastically speed up deploy times (testing on my SATA SSD showed a 14x improvement, 0.075s when on vs 1.058s when off) when deploying to the same drive and filesystem. It is off by default as it could cause issues with munging sounds and movies if the game is running and using the sound .lvls/movies at the same time. If you're aware of that though and can work around it then I reccomend turning it on in the Munge Config Editor as the speedup is well worth it.
- Added "Ask for Confirmation Before Clean" setting. Off by default. When turned on WorldEdit will ask for confirmation before beginning a clean.
- Added detection and workarounds to allow compatibility with vkd3d. I've not tested WorldEdit running on Proton but it now works with vkd3d on Windows which seems like a good first step.

- Fixed being able to start a munge without resolving the Browse for Game Install popup.

- Fixed saved platform in munge config not being loaded.

Entity Groups

Entity Groups let you place down multiple entities at once. The entities do not need to be of the same type and all entity types are supported.

There are three main tools for creating an Entity Group. They are currently all found under "File".

- Save Selection as Entity Group
   This saves the currently selection as an Entity Group. The Entity Group will be centred on `0, 0, 0` before saving.

- Save World as Entity Group
   This saves the entire world as an Entity Group.

- Save Layer as Entity Group
   This saves a specific layer as an Entity Group.

Saved Entity Groups will have the uncreative extension `.eng`.

An Entity Group can be placed by going into the "Create" menu (either through the main menu bar or using the spacebar shortcut) and using the "From Group" submenu. Known Entity Groups will be listed there and only need to be clicked on to be created.

Entity Groups are found the same way as assets by looking through your mod's Data Folder. Unlike assets once loaded they will not be reloaded automatically in the background (but selecting the same group from the create menu will reload it). Both `.eng` and `.obg` (ZE object groups) will be looked for.

Name uniqueness is enforced for entities placed into a world from an Entity Group but most entities that reference each other will have their references updated to stay linked correctly whenever an entity is forced to rename.
